# VELARA — Brief de mejoras para el sitio web

## 1. Objetivo

Mejorar el sitio web de **VELARA TALLER S.A.S.** para convertirlo en una landing comercial moderna, profesional y enfocada en generar cotizaciones por WhatsApp.

**Importante:** no crear un sitio completamente diferente desde cero si ya existe una estructura funcional. Analizar primero el código actual y realizar mejoras incrementales, conservando lo que ya funciona.

El objetivo principal del sitio NO es vender mediante carrito/e-commerce.

El objetivo es:

> **Visita → entiende la solución → ve trabajos reales → genera confianza → solicita cotización por WhatsApp.**

---

# 2. Identidad de marca

## Logo

Existe un logo maestro oficial de VELARA.

Debe utilizarse exactamente como referencia de marca.

**NO:**
- redibujar el logo;
- cambiar su geometría;
- modificar proporciones;
- cambiar arbitrariamente sus colores;
- agregar efectos innecesarios;
- crear una versión alternativa del símbolo.

El logo oficial contiene:
- isotipo negro;
- acento rojo integrado;
- wordmark VELARA;
- detalle rojo en la "A";
- símbolo ®;
- descriptor: **SOLUCIONES A MEDIDA**.

---

# 3. Dirección visual

La página debe sentirse:

- profesional;
- premium;
- automotriz;
- industrial;
- moderna;
- limpia;
- confiable;
- orientada a fabricación;
- visualmente fuerte.

Evitar que parezca:

- una plantilla genérica;
- una tienda de productos;
- una página saturada de rojo;
- una página excesivamente corporativa;
- una página llena de texto;
- una página artificialmente "hecha por IA".

## Paleta

Base:

- Negro
- Blanco
- Gris
- Gris oscuro
- Rojo como color de acento

El rojo debe utilizarse principalmente para:

- CTA;
- pequeños detalles;
- indicadores;
- elementos interactivos;
- acentos visuales.

**No utilizar rojo como fondo dominante de toda la página.**

Texto secundario:



Crear una sección:

## ¿POR QUÉ VELARA?

Cada solución se adapta al proyecto.

Desarrollamos soluciones según las necesidades del cliente.

### INSTALACIÓN
Cuando el proyecto lo requiere, acompañamos el proceso.

### ATENCIÓN PERSONALIZADA

Evitar afirmaciones no verificadas como:

- "los mejores";
- "número 1";
- "líderes de Colombia";
- "garantizado el mejor precio".

No inventar cifras ni certificaciones.

# 12. WhatsApp

WhatsApp es el canal comercial principal.

Debe existir un CTA visible en:

- Header;
- Hero;
- tarjetas de servicios;
- portafolio cuando sea apropiado;
- CTA final;
- botón flotante.

Pero evitar saturar visualmente la interfaz.

El CTA principal debe ser:

**Cotizar por WhatsApp**

No usar frases ambiguas como:

- "Comprar ahora";
- "Añadir al carrito";
- "Comprar producto".

---

# 13. Diseño responsive

La página debe funcionar correctamente en:

- Desktop
- Tablet
- Mobile

Mobile es especialmente importante porque gran parte del tráfico comercial puede venir desde WhatsApp.

En móvil:

- CTA de WhatsApp visible;
- textos cortos;
- botones grandes;
- imágenes optimizadas;
- navegación sencilla;
- evitar secciones excesivamente altas;
- evitar animaciones que ralenticen la página.

---

# 14. UX

El usuario debe poder entender en pocos segundos:

1. Qué hace VELARA.
2. Qué servicios ofrece.
3. Qué tipo de trabajos realiza.
4. Cómo solicitar una cotización.
5. Cómo contactar por WhatsApp.

Evitar obligar al usuario a leer grandes bloques de texto.

Usar:

- títulos claros;
- tarjetas;
- fotografías;
- espacios en blanco;
- jerarquía visual;
- microinteracciones discretas.

---

# 15. Animaciones

Utilizar animaciones únicamente cuando aporten valor.

Preferir:

- fade-in;
- desplazamientos suaves;
- hover;
- aparición progresiva;
- pequeñas transiciones.

Evitar:

- animaciones exageradas;
- elementos que reboten;
- demasiados efectos;
- parallax excesivo;
- animaciones que afecten el rendimiento.

---

# 16. SEO

Optimizar como mínimo:

### Title

VELARA | Soluciones a medida para vehículos y negocios

### Meta description

Forros para carros, tapicería automotriz, carpas, toldos y soluciones a medida. Solicita tu cotización con VELARA.

Utilizar correctamente:

- H1;
- H2;
- H3;
- alt text;
- metadata;
- Open Graph.

No llenar el contenido de palabras clave artificialmente.

---

# 17. Performance

Antes de agregar librerías nuevas, revisar las existentes.

Priorizar:

- imágenes WebP/AVIF cuando sea posible;
- lazy loading;
- dimensiones explícitas para imágenes;
- evitar JavaScript innecesario;
- minimizar solicitudes;
- evitar videos pesados en autoplay;
- mantener buena velocidad en móvil.

---

# 18. Regla importante para imágenes

No inventar fotografías de productos que VELARA no tenga.

Cuando existan imágenes reales en el proyecto, utilizarlas primero.

Si falta una imagen:

- dejar un placeholder claramente identificable;
- no inventar trabajos reales;
- no afirmar que una imagen generada corresponde a un trabajo real.

---

# 19. Código existente

Antes de modificar:

1. Revisar la estructura completa del proyecto.
2. Identificar entry points.
3. Identificar CSS global.
4. Identificar componentes/secciones.
5. Identificar assets.
6. Identificar scripts.
7. Identificar dependencias.

No eliminar funcionalidades existentes sin comprobar su uso.

No reemplazar todo el proyecto simplemente para conseguir un diseño nuevo.

---

Trabajar de manera incremental:

```text

↓
PROPONER
↓
MODIFICAR
↓
PROBAR
↓
```

- consola;
- errores JS;
- rutas;
- imágenes;
- responsive;
- botones;
- enlaces;
- WhatsApp;
- rendimiento.

- inventar servicios;
- inventar testimonios;
- inventar clientes;

- inventar cifras;

- romper funcionalidades existentes;

- qué estructura ya existe;
- qué partes funcionan;
- qué partes necesitan mejora;
